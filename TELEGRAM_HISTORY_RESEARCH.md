# Чтение старых сообщений Telegram-группы

Проверено 16 октября 2026 года по официальной документации Telegram и первичным материалам Go-библиотеки.

## Краткий вывод

Да, старую историю группы можно читать, но не через Telegram Bot API. Для этого нужен отдельный Telegram-клиент, авторизованный как обычный пользователь, и MTProto API. Переписывать проект на другой язык не требуется: для Go есть `gotd/td`, клиент MTProto на чистом Go. Этот клиент может работать в том же приложении, что и Bot API-клиент, но это будут две отдельные авторизации и две сессии.

Чтение будет возможно в пределах того, что видит авторизованный пользовательский аккаунт. Он должен иметь доступ к группе; старые сообщения могут быть недоступны, если история для новых участников скрыта, сообщения удалены или Telegram не отдаёт соответствующий фрагмент истории.

## Ограничения Bot API

Bot API предоставляет боту поток updates — новые события, доставляемые через `getUpdates` или webhook. Telegram хранит ожидающие updates не дольше 24 часов. Это не архив чата: `getUpdates` не позволяет запросить историю группы за произвольный период или загрузить сообщения, отправленные до запуска бота.

Какие новые сообщения бот видит, зависит от privacy mode и прав бота: администратор или бот с отключённым privacy mode получает сообщения группы, кроме сообщений других ботов; при включённом режиме набор сообщений ограничен командами, ответами и сообщениями, адресованными боту. Эти правила влияют на будущий сбор, но не дают доступа к прошлой истории.

Источники: [Bot API: получение updates и срок хранения](https://core.telegram.org/bots/api#update), [Bots FAQ: какие сообщения получает бот](https://core.telegram.org/bots/faq#what-messages-will-my-bot-get).

## Доступ к истории через MTProto

Telegram описывает MTProto как API для приложений-клиентов. Метод [`messages.getHistory`](https://core.telegram.org/method/messages.getHistory) возвращает историю peer с пагинацией по ID и дате. Документация явно ограничивает вызов пользовательской авторизацией («Only users can use this method»); среди возможных ошибок указаны недействительный или приватный канал/группа. Следовательно, bot token сам по себе не подходит для чтения старой истории.

Пользовательский клиент должен авторизовать Telegram-аккаунт. Для приложения разработчик получает `api_id` и `api_hash` на [my.telegram.org](https://my.telegram.org) согласно [официальной инструкции Telegram](https://core.telegram.org/api/obtaining_api_id). При первом входе пользователь подтверждает вход кодом, отправленным Telegram; при включённой двухэтапной проверке потребуется пароль 2FA. Telegram описывает эти варианты в [документации авторизации пользователя](https://core.telegram.org/api/auth).

Аккаунт должен состоять в нужной приватной группе или иметь доступ к публичной группе. Даже при членстве история до вступления может быть скрыта: Telegram отражает это флагом `hidden_prehistory` в [объекте channelFull](https://core.telegram.org/constructor/channelFull). В настройке группы «История чата для новых участников» видимость определяет, увидят ли новые участники ранние сообщения ([официальные строки интерфейса Telegram](https://translations.telegram.org/ru/ios/groups_and_channels/)). Также история не гарантируется для уже удалённых сообщений или фрагментов, которые Telegram считает недоступными. Документация по [работе с updates и заполнению пробелов истории](https://core.telegram.org/api/updates) предупреждает, что очень старые сообщения супергрупп/каналов могут быть недоступны.

Это применимо и к уже существующей группе: отдельный пользовательский аккаунт может запросить доступную ему прошлую историю после вступления. Фактический охват старых сообщений определяется настройкой истории и доступом аккаунта, а не датой добавления бота. Для существующей приватной группы нужно добавить в неё пользовательский аккаунт, который будет выполнять импорт.

## Поддержка Go

[`gotd/td`](https://github.com/gotd/td) — клиент Telegram MTProto на Go, работающий как с пользовательскими, так и с бот-авторизациями. Репозиторий заявляет полную реализацию MTProto 2.0 на чистом Go, прямой вызов методов Telegram, поддержку пользовательской авторизации и подключаемое хранение сессии.

В официальных примерах библиотеки есть [userbot](https://github.com/gotd/td/tree/main/examples/userbot), где выполняется вход пользователя и хранится сессия, и [пример диалогов](https://github.com/gotd/td/tree/main/examples/dialogs) с `query.Messages(...).GetHistory`. В [README примеров](https://github.com/gotd/td/blob/main/examples/README.md) перечислены `APP_ID`, `APP_HASH` и `SESSION_FILE`; там же отдельно сказано не публиковать api credentials. Значит, переход на Python, JavaScript или другой язык не нужен: чтение истории можно реализовать на Go рядом с текущим ботом.

## Секреты и эксплуатация

- `api_id` и `api_hash` — реквизиты приложения; хранить в переменных окружения/секретах развёртывания, не коммитить. Репозиторий `gotd/td` предупреждает, что `APP_ID`/`APP_HASH` нельзя распространять и их трудно сменить.
- Файл пользовательской сессии содержит авторизованную сессию. Практически его нужно считать секретом уровня входа в аккаунт: хранить в отдельном защищённом volume с ограниченными правами, не класть в `data/bot.json`, не отправлять в логи и не включать в резервные копии без шифрования.
- Первичную авторизацию следует выполнить под контролем владельца аккаунта, вводя код и 2FA-пароль в доверенном окружении. На VPS затем используется сохранённая сессия, а не повторный ввод кода при каждом запуске.
- Использовать отдельный аккаунт, выделенный для импорта, с минимальными правами. MTProto-сессия имеет доступ ко всем данным, доступным этому аккаунту, а не только к одной группе.
- Соблюдать [условия Telegram API](https://core.telegram.org/api/terms), включая требования к приватности и безопасности; не выполнять действия от имени пользователя без его ведома и согласия.

## Практическая рекомендация для этого бота

Оставить текущий Go-бот и Bot API для новых сообщений. Добавить отдельный компонент импорта на `gotd/td`, который один раз авторизуется как пользователь и читает доступную историю указанной группы через MTProto с пагинацией и фильтром по датам. Импортированные сообщения следует передавать в существующую логику разбора прогнозов, сохраняя исходные дату, автора и ID сообщения и делая импорт идемпотентным, чтобы повторный запуск не создавал дубли.

До разработки проверить доступность истории на практике: пользовательский аккаунт должен быть в группе, открыть её обычным Telegram-клиентом и убедиться, что сообщения нужного периода видны. Для групп с включённой скрытой историей чтение через API это ограничение не обойдёт. После разового импорта текущий Bot API продолжит собирать новые прогнозы; при необходимости надёжного непрерывного восстановления пропусков можно также поддерживать пользовательский MTProto-клиент подключённым и обрабатывать его updates.

Это сложнее поддержки одного bot token: появляется отдельная пользовательская авторизация и более чувствительный session-файл. Но для разового/периодического backfill это прямой и совместимый с Go путь.
