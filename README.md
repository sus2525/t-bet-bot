# t-bet-bot

Telegram-бот для футбольных прогнозов.

Go-бот собирает прогнозы в группе, обновляет реальные результаты и считает очки по турам командой `/result`, а `/stats` показывает общий зачёт и очки по турам. Состояние хранится в SQLite-файле `data/bot.db`.

## Создание и запуск

1. В [@BotFather](https://t.me/BotFather) создайте бота командой `/newbot` и сохраните токен.
2. Вызовите `/setprivacy`, выберите бота и нажмите **Disable**, чтобы он получал обычные сообщения с прогнозами.
3. Добавьте бота в группу. Ему нужно разрешить отправлять сообщения.
4. Получите токен на [football-data.org](https://www.football-data.org/client/register). Бесплатный тариф включает Лигу чемпионов, но результаты могут приходить с задержкой.
5. Установите на VPS Docker Engine и Docker Compose plugin, скопируйте проект и создайте `.env` рядом с `docker-compose.yml`:

   ```env
   TELEGRAM_BOT_TOKEN=токен_от_BotFather
   FOOTBALL_DATA_TOKEN=токен_из_football-data.org
   ```

6. Запустите контейнер:

   ```sh
   docker compose up -d --build
   docker compose logs -f
   ```

Compose подключает `./data` в контейнер. Не удаляйте этот каталог: в нём сохранены прогнозы, снимки матчей, очки по турам, результаты расчётов и последний обработанный Telegram update. Этот volume переживает пересборку и перезапуск Docker-контейнера. Используйте один экземпляр бота на токен.

Compose подключает постоянный каталог `./data` с VPS к `/data` в контейнере. База SQLite и сопутствующие файлы WAL лежат прямо в `./data/bot.db`, поэтому доступны на VPS и переживают пересборку и перезапуск контейнера. Отдельный контейнер сервера БД не нужен.

При каждом запуске контейнер автоматически исправляет владельца и права каталога базы, затем запускает приложение от отдельного непривилегированного пользователя `bot`. Поэтому существующий `./data/bot.db`, созданный root или с прежними правами, должен открыться после обычного `docker compose up -d --build`; содержимое базы при исправлении прав сохраняется. Если VPS запрещает `chown` на bind mount (например, каталог находится на некоторых сетевых файловых системах), контейнер сообщит об ошибке в `docker compose logs`.

Docker хранит последние примерно 100 МБ логов контейнера: четыре файла по 25 МБ с ротацией.

Файл базы будет находиться в `./data/bot.db` относительно каталога проекта. Для просмотра SQL установите `sqlite3` на VPS и выполните `sqlite3 ./data/bot.db '.tables'`.

Каждый новый запуск без `data/bot.db` создаёт пустую SQLite-базу. Старый `data/bot.json` игнорируется и не импортируется; его можно удалить вручную, если он больше не нужен. Запускайте только одну копию бота с этой базой одновременно.

Бот работает через long polling и сразу сохраняет прогнозы и checkpoint последнего обработанного update в `data/bot.db`. Telegram держит необработанные updates не более 24 часов. Bot API не умеет читать произвольную старую историю группы. Для анализа более старых сообщений понадобится MTProto-клиент с авторизацией обычного Telegram-аккаунта; исследование этого варианта находится в [TELEGRAM_HISTORY_RESEARCH.md](TELEGRAM_HISTORY_RESEARCH.md). В `docker compose logs -f` бот пишет полученный текст и контекст reply, решение парсера и текст отправленного ответа; длинные тексты обрезаются, токены маскируются.

В группах с включёнными темами бот отвечает в тот же топик, где была вызвана команда, в том числе для отложенных ответов `/tour` и `/result`.

Старый прогноз можно учесть, переслав его в группу после запуска бота, или ответив любым текстом на исходное сообщение. Если текст reply сам не является прогнозом или командой, бот читает сообщение-якорь и записывает прогноз его автору; исходный текст должен соответствовать формату прогноза. Повторные ответы на тот же прогноз не дублируют запись. Для пересылок, где Telegram передал ID исходного автора, прогноз записывается этому автору, а дата берётся из исходного сообщения. При скрытом авторе пересылки бот использует стабильный анонимный ID по имени, которое предоставил Telegram. Пересланные посты от каналов не учитываются как прогнозы конкретных игроков. Бот не может сам просмотреть старые сообщения, которые уже лежат в истории группы.

## Установка Go в Ubuntu WSL

Для Linux x86-64 скачайте официальный архив Go 1.27.2, проверьте SHA-256 и установите его:

```sh
curl -fL -o /tmp/go1.27.2.linux-amd64.tar.gz https://go.dev/dl/go1.27.2.linux-amd64.tar.gz
printf '%s  %s\n' ecbadb99091a3f46e31f5f934b068b1864eafa7995211b39eaddf76996045fe5 /tmp/go1.27.2.linux-amd64.tar.gz | sha256sum -c -
sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf /tmp/go1.27.2.linux-amd64.tar.gz
printf '\nexport PATH=/usr/local/go/bin:$PATH\n' >> ~/.profile
export PATH=/usr/local/go/bin:$PATH
go version
```

Команды выполняются в терминале WSL. Для другой архитектуры выберите архив и контрольную сумму на [странице загрузок Go](https://go.dev/dl/).

## Запуск тестов

Из корня проекта, если установлен Go 1.27 или новее, GCC и SQLite development library (`libsqlite3-dev` в Ubuntu):

```sh
go test ./...
```

Если Go не установлен, запустите тесты в официальном Go-образе через Docker:

```sh
docker run --rm -v "$PWD":/src -w /src golang:1.27.2-alpine sh -c 'apk add --no-cache build-base sqlite-dev && CGO_ENABLED=1 go test ./...'
```

Для тестов не нужны токены Telegram и football-data.org: обращения к API подменяются в тестах. Тесты используют временные SQLite-файлы и не меняют `data/bot.db`.

## Формат прогнозов

Отправляйте один или несколько прогнозов сообщением, по одному матчу на строку:

```text
1. Ланс — Спортинг: 1:1
2) Сабах - Славия Прага 0:2
```

Поддерживаются нумерация `1.` или `1)`, разделители `—`, `–`, `-`, а также строка с двоеточием перед счётом или без него. Бот сохраняет прогноз вместе с именем участника, Telegram username, временем сообщения и номером матча. Если тур был выдан через `/tour`, бот сохраняет также ID матча, связанный с этим номером.

## Взаимодействие с ботом

До игр выдайте участникам список матчей: `/tour 2`. Для стадий плей-офф используйте `/tour 1/16`, `/tour 1/8`, `/tour 1/4`, `/tour 1/2` или `/tour 1/1`. Бот запрашивает у football-data.org текущий сезон и стадию, сохраняет матчи в SQLite и использует кэш повторно. Команда `/tour data` берёт последний список, сохранённый в этом чате. Список выглядит так:

```text
Скопируйте список, допишите свой счёт после двоеточия и отправьте в чат. Номера не меняйте.
Пример: «1. Ланс — Спортинг: 1:1»

1. Ланс — Спортинг:
2. Сабах — Славия Прага:
```

Участник дописывает счёт после двоеточия в каждой нужной строке. Номер связывает строку со скрытым ID матча из последнего списка `/tour` этого чата. Бот сохраняет эту связь при получении прогноза, поэтому последующие изменения названия команды в API не мешают подсчёту. Старые прогнозы без ID сопоставляются по русским и английским названиям. Полученные матчи тура кэшируются; начисления появляются после `/result`.

Во всех ответах команд, где перечисляются участники, бот показывает имя и фамилию вместе с Telegram username: `Usov V (usov_vlad)`. Если Telegram не передал имя или username, выводится доступная информация. Для старых записей профиль обновится, когда участник отправит новый прогноз.

После матчей обновите реальные счета и начислите очки одной командой:

```text
/result
```

`/result` получает результаты из football-data.org, сопоставляет их с прогнозами и показывает фактические счета и очки. Для лиговой фазы укажите номер тура. Для плей-офф укажите стадию: `1/16`, `1/8`, `1/4`, `1/2` или `1/1` (финал). Бот передаёт в API сезон и фильтр `stage`: `PLAYOFFS`, `LAST_16`, `QUARTER_FINALS`, `SEMI_FINALS` или `FINAL`, согласно [документации football-data.org](https://docs.football-data.org/general/v4/competition.html). Названия стадий из ответов API нормализуются (например, `LAST_32` тоже учитывается как `1/16`), и очки сохраняются в той же таблице, что и туры 1–8. Если API не вернул матчи по фильтру стадии, бот загружает сезон и отбирает нужную стадию локально. Username можно добавить после номера тура или стадии:

```text
/result
/result 2
/result 2 usov_vlad
/result 2 --refresh
/result 2 usov_vlad --refresh
/result 1/8
/result 1/8 usov_vlad
/result 1/8 --refresh
/result data usov_vlad
```

Первая команда в примере выше показывает запуск расчёта всех сохранённых прогнозов без фильтра тура. `/result 2` считает второй тур для всех игроков. `/result 2 usov_vlad` также сохраняет очки всех игроков, но показывает только подробный разбор прогнозов указанного участника. В одиночку username в `/result` не используется. Финальные результаты тура сохраняются отдельно от снимка всего сезона, чтобы повторный `/result 2` использовал сохранённые данные. Флаг `--refresh` принудительно запрашивает тур у API, заменяет сохранённые результаты и пересчитывает очки всех игроков; для этой команды нужен `FOOTBALL_DATA_TOKEN`.

`/result data username` показывает только подробный расчёт прогнозов этого игрока по уже сохранённым матчам, без отдельного списка реальных результатов. Команда не запрашивает API и не меняет сохранённые данные. Обычный `/result` использует сохранённые финальные результаты; если счёта ещё нет, бот обновляет тур через API.

Пример результата:

```text
Результаты Лиги чемпионов по турам

Сезон 2026/2027 · тур 1
Ланс—Спортинг 0:2
Арсенал—Лилль 3:0
Очки:
Анна Иванова (anna_ivanova) +8 (точно: 1)
Иван Петров (ivan_petrov) +1 (точно: 0, пропусков: 2)
```

Для матчей плей-офф используйте те же команды, например `/tour 1/8` для списка матчей и `/result 1/8` для подсчёта. Все игры стадии (в том числе оба матча пары, если API относит их к этой стадии) оцениваются вместе; каждый прогноз привязан к ID конкретного матча. В `/stats` после колонок туров 1–8 идут колонки `1/16`, `1/8`, `1/4`, `1/2` и `ФИН`; очки всех стадий входят в общий рейтинг.

Очки игроку за один тур учитываются один раз. Если финальный счёт по одному из его прогнозов ещё не появился, тур для этого игрока останется ожидающим; после обновления API запустите `/result` снова. Пропущенный прогноз даёт 0 за этот матч; пропуск всего тура сохраняется как 0 очков после завершения всех матчей тура. Точный счёт также увеличивает показатель «точно» в `/stats`.

Посмотреть накопительную таблицу текущей группы:

```text
/stats
```

```text
Таблица Лиги чемпионов · сезон 2026/2027
Игрок             Очки/точно   1   2   3   4   5   6   7   8
─────────────────────────────────────────────────────────────
1. Анна Иванова (anna_ivanova)  8/1  +8   ·   ·   ·   ·   ·   ·   ·
2. Иван Петров (ivan_petrov)    1/0  +1   ·   ·   ·   ·   ·   ·   ·

Игроки отсортированы по общему числу очков. В колонке «Очки/точно» второй показатель — число точных счетов. · — тур ещё не оценён.
```

Справка по доступным командам: `/help`. Диагностика: `/debug` показывает uptime процесса и последние общие логи. Подробные логи с текстом сообщений и reply доступны только в `docker compose logs -f`.

Команды можно отправлять и в адресном виде: `/tour@ИмяБота`, `/result@ИмяБота`, `/stats@ИмяБота`, `/help@ИмяБота`, `/debug@ИмяБота`.

## Источник и задержки

Основной API — football-data.org, соревнование `CL`. Запросы результатов и расписания ограничены интервалом около 18 секунд, чтобы соблюдать лимит бесплатного тарифа. Если API недоступен, бот использует последний сохранённый снимок сезона, когда он есть; неизвестный счёт не трактуется как 0:0 и не даёт очков.

Сравнение football-data.org, API-Football и Sportmonks, их тарифов и заявленной свежести находится в [RESULTS_API_RESEARCH.md](RESULTS_API_RESEARCH.md). Ни один из изученных поставщиков не гарантирует точное время появления финального счёта. Переключение на альтернативу требует API-токена и проверки доступа к нужному сезону.
