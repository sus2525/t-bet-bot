# Цель проекта

Telegram-бот на Go для сбора футбольных прогнозов в группе и накопления статистики. Бот запускается в Docker на VPS, хранит состояние в SQLite `data/bot.db`, подключённой как постоянный `./data:/data` volume.

## Команды

### `/tour [matchday|stage]` и `/tour data`

- Публиковать нумерованный шаблон без счёта в строках матчей: `1. Ланс — Спортинг:`. Вверху объяснять заполнение и показывать пример.
- Для указанного тура получать матчи текущего сезона через `season` и `matchday` в API. Для плей-офф принимать `1/16`, `1/8`, `1/4`, `1/2`, `1/1`; запрашивать `stage` (соответственно `PLAYOFFS`, `LAST_16`, `QUARTER_FINALS`, `SEMI_FINALS`, `FINAL`), нормализовать aliases из API и при пустом stage-фильтре сверять полный сезон. Сохранять результаты в SQLite и использовать кэш при повторном запросе.
- Сохранять для каждого чата соответствие номеров тура и ID матчей. При получении прогноза с номером привязывать его к ID из последнего списка этого чата.

### `/result [matchday|stage] [username] [--refresh]`

- Получать расписание и реальные счета Лиги чемпионов через football-data.org (`CL`, `/v4/competitions/CL/matches`) с `FOOTBALL_DATA_TOKEN`; команда обновляет результаты и считает прогнозы.
- Без номера тура обрабатывать все сохранённые прогнозы чата; username допускается только вместе с номером тура или в `/result data username`.
- Всегда пересчитывать и сохранять очки всех игроков выбранного тура. Если указан username, показывать только подробный разбор этого игрока.
- `--refresh` принудительно получать матчи указанного тура/стадии из API, обновлять кэш и пересчитывать очки с учётом изменённых счетов.
- Получать `matchday` из данных каждого матча и показывать результаты хронологически по сезону и туру.
- Сопоставлять прогнозы по сохранённому ID матча; старые записи без ID сопоставлять по названиям команд в соответствующем сезоне. Время начала матча не ограничивает подсчёт.
- Если финального счёта нет, явно показывать статус и не начислять очки. Не засчитывать тур игроку, пока все его прогнозы этого тура не оценены.
- Учитывать только последний прогноз игрока на матч. Начислять 5 за точный счёт, 3 за исход и точную разницу, 1 за победителя; иначе 0.
- Начислять очки игроку за сезонный тур или стадию один раз. Восемь туров лиговой фазы и пять стадий плей-офф используют одну таблицу; ключи плей-офф 9..13 означают 1/16..финал. Повторный `/result` обновляет результаты и показывает сохранённый разбор без повторного начисления.
- Во всех ответах, где перечисляются игроки, показывать `Имя Фамилия (username)` при наличии обоих полей; иначе показывать доступное значение. Username без `@`.
- Без username выводить результаты матчей и очки игроков по турам; с username добавлять подробный разбор его прогнозов.
- Не суммировать начисление одного чата, игрока, сезона и тура повторно.

### `/stats`

Показывать моноширинную таблицу с общими очками, точными счетами и очками по восьми турам лиговой фазы и пяти стадиям плей-офф (`1/16`, `1/8`, `1/4`, `1/2`, финал), отсортированную по общему числу очков; использовать формат `Имя Фамилия (username)`, если оба значения известны.

### `/help` и `/debug`

- `/help` показывает справку по пользовательским командам и краткий пример прогноза.
- `/debug` показывает uptime процесса и последние строки логов. Сохранять обычный вывод логов в stderr и не раскрывать секреты в ответе.

## Прогнозы и история

- Принимать несколько строк прогнозов формата `1. Команда — Команда: 1:1`, а также нумерацию `1)` и разделители `—`, `–`, `-`; двоеточие перед счётом необязательно.
- Сохранять автора, чат, время сообщения, пары команд и счёт прогноза.
- Сохранять прогнозы, снимки матчей, итоги туров и последний обработанный Telegram update в SQLite `data/bot.db`; Compose должен подключать постоянный `./data:/data` volume.
- Telegram Bot API не предоставляет метод чтения произвольной старой истории; updates хранится до 24 часов. Для бэкфилла истории требуется MTProto-сессия пользователя.

## Развёртывание

- Использовать Go и Docker. Telegram-токен передавать через `TELEGRAM_BOT_TOKEN`, football-data.org токен через `FOOTBALL_DATA_TOKEN`; секреты не помещать в репозиторий.
- Данные хранить в подключённом volume и переживать рестарт контейнера.
- Пользовательские инструкции и сценарии использования держать актуальными в `README.md`.
